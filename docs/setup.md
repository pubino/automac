# Setting up a Mac (new, or wiped and restored)

Everything this repository needs can be rebuilt from the remote plus one command. VM
images are **not** backed up: they are rebuilt from pinned inputs.

## Steps

1. **Install the tools** that are not part of macOS:

   ```zsh
   xcode-select --install          # git; skip if Xcode or the Command Line Tools are present
   brew install uv gh              # https://brew.sh first if Homebrew is missing
   gh auth login
   ```

   Install Docker Desktop if you will run `scripts/test.sh` (it provides `docker` and
   `docker-compose`). `jq`, `curl`, `codesign` and `spctl` ship with macOS.

2. **Clone and bootstrap:**

   ```zsh
   gh repo clone pubino/automac && cd automac
   scripts/bootstrap.sh --dry-run    # see what it will do
   scripts/bootstrap.sh              # add --ipsw to also fetch macOS (~25 GB)
   ```

   It installs the pinned Tart, creates `.env`, sets this clone's git identity to your
   GitHub noreply address, creates `.venv`, and installs the agent skill. It ends with a
   **TO DO** list of anything it could not do. Re-run it until that list is empty or holds
   only what you chose to skip.

3. **Rebuild the base image** (about 30 minutes):

   ```zsh
   set -a; source .env; set +a
   examples/zsh/tartvm doctor
   examples/zsh/tartvm image --ipsw "$TARTVM_HOME/cache/UniversalMac_<version>_Restore.ipsw"
   ```

4. **Check it all works:** `./scripts/test.sh --local`, then smoke-test any `.app` with
   `examples/zsh/tartvm test path/to/MyApp.app`.

## What lives where

| Item | In git? | After a wipe |
| --- | --- | --- |
| Docs, examples, tests, skill, prompts, CI | Yes | Restored by the clone. |
| Pinned versions and hashes (`tartvm.lock.json`, `uv.lock`) | Yes | Restored by the clone. |
| Tart binary (`$TARTVM_HOME/tools/`) | No | `bootstrap.sh` downloads and verifies it again. |
| macOS IPSW (`$TARTVM_HOME/cache/`) | No | `bootstrap.sh --ipsw` downloads and verifies it again. |
| VM images and clones (`$TARTVM_HOME/tart/`) | No | Rebuilt with `tartvm image`. Nothing in them is worth keeping. |
| VM-only SSH key and guest password (`$TARTVM_HOME/ssh/`) | No | Regenerated by `tartvm image`. They only open these local VMs, so losing them is harmless: the old images are gone too. |
| Logs (`$TARTVM_HOME/logs/`) | No | Not needed. Keep JSON reports in the project that produced them. |
| `.env` | No (gitignored) | Created by `bootstrap.sh` from `example.env`. Re-apply any optional settings you changed. |
| `.venv` | No | `uv sync --frozen` (run by `bootstrap.sh`). |
| Git identity for this clone | No (local git config) | Set by `bootstrap.sh` from `gh`. **Until it runs, commits here use your global identity**, which may be your real name and email in a public repo. |
| Skill symlink in `~/.claude/skills` | No | Created by `bootstrap.sh`. |
| GitHub auth (`gh auth login`) | No | Step 1. |

`$TARTVM_HOME` (default `~/tartvm-state`) is safe to delete at any time; the steps above
recreate it.

## Things outside this repository

- **Projects that copied the examples** have their own `.env`, state directory and VM
  images; restore them with that project's own setup steps. Their harnesses read the same
  kind of settings (`TARTVM_*`).
- **A self-hosted CI runner** on this Mac must be registered again with GitHub
  (Settings → Actions → Runners), with its labels, and the repository variables
  (`TARTVM_TART`, `TARTVM_HOME`) pointed at the new paths. See [ci.md](ci.md).

## Updating the pins

To move to a new Tart or macOS release, edit `tartvm.lock.json` in a reviewed commit:

- **Tart:** the release tarball's URL and SHA-256 (`shasum -a 256 tart.tar.gz`). Check the
  `TeamIdentifier` with `codesign -dv` after extracting. If the Team ID changes, find out
  why before accepting it.
- **IPSW:** the URL and SHA-1 from Apple's catalog (the `catalog` URL in the lock).

Then run `scripts/bootstrap.sh --ipsw` and rebuild the image.
